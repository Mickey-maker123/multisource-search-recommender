# 一次任务推荐怎样产生

假设库中既有《设备 A 滤芯更换手册》，也有工单表。查询“更换滤芯”和查编号 `00017` 对系统的要求不同，以下步骤解释两个入口如何复用同一份资料。

1. **接入时保留业务语义。** 适配器交给引擎对象标识、版本、正文或字段、来源位置与可见范围。文本按片段保存；表格行用相对文件名与稳定主键关联，工单号映射为字符串后保留前导零。解析前检查解析许可和访问范围。
2. **检索时走不同的索引。** Java 向 Elasticsearch 发关键词与向量检索；本地 BGE-M3 把文本转为 1024 维向量。混合查询用倒数排名融合（RRF）合并两路名次。精确字段条件另行匹配。分页继续验证对象权限、版本及结果是否有效。
3. **推荐时考虑用途。** 阅读当前对象时，`kind=related` 以该对象为参考。个人入口 `kind=personal` 接收带过期时间的当前任务，同时考虑显式偏好、订阅和已许可行为。缺少信号时可能回退到近期可访问资料。返回的 `reasons` 可说明命中的通道或信号，用户可打开原文判断适用性。
4. **展示时为操作寻找上下文。** 对有当前任务的 Markdown、纯文本卡片，先尝试补全截断行，再在同一文档中用 BM25 比较候选片段，并检查原卡中重要的行内代码标识。选段沿用该文档的来源与版本，支持回退到原选段策略。此环节只更新展示文字与位置。
5. **打开时再核对。** 正文读取校验当前身份、祖先访问权限和对象版本。若文件在检索后变动，页面提示读者重新定位。原文响应含段落或页码、字符区间及用于后续分页的版本保护值。

**判断效果时要看具体指标。** 针对 Starlette 与 Typer 两个来源的 12 个代理任务，9 个有答案任务在前五卡片上可见的必要操作由 9/18 增至 11/18，其中 3 项改善、1 项退化、5 项持平。评分来自助手对原文的核对。其余 3 个库内缺答案任务仍会返回相关资料。一次任务推荐可能只是内容相关，开发者应将片段和来源呈现给读者。

**部署边界。** 本版把多个来源接到同一套 H2 与搜索索引。源系统通过目录扫描、适配器或写入接口提交更新，权限或删除在更新被接收后生效。跨单位独立索引上的授权查询与结果汇总需要另外实现。运行中可在管理页面分别查看解析、关键词索引、向量索引及模型队列状态。
